# wb2api 1.10.0

> 历史版本公告。项目名称已统一，旧下载链接已移除，安装包旧前缀以 `***` 隐去；内容保留当时的更新与验证记录，不代表本轮重新验证。

本次更新把「用量日志 → 请求动态」从每 3 秒轮询改为服务端推送，并完善了账号到期排行的操作提示。

## 更新内容

- **请求动态改为实时推送（SSE）**。原先打开日志面板时，前端每 3 秒请求一次 `/api/logs/requests`：一个标签页每小时 1200 次请求，每次都走完鉴权、线程池、一次 SQL 采样与 JSON 序列化，而绝大多数时候结果完全相同。现在改为一条长连接，空闲时比较内存状态、按需推送，并每 10 秒兜底核对数据库；折叠卡片、切走面板或标签页转入后台会立即断开连接，服务端随之停止采样。
  - 推送连接本身有数量上限，超出或代理不转发 SSE 时自动退回 **15 秒**低频轮询（原为 3 秒），界面照常可用。
  - 「已耗时」由浏览器本地走表，服务端不再为它每秒推帧。
  - 推送鉴权使用短时票据（2 分钟有效、只能读取该推送），管理员令牌不会出现在 URL 中。
- **账号到期排行的操作按钮统一为系统 tooltip**。上移/下移、积分明细、重新采集的说明改为与其他面板一致的悬浮提示，并明确写出「会改变真实账号使用顺序」；排序按钮增加常驻底色，与只读操作区分开，避免误点。「恢复自动排序」同样补充了说明。
- **修复打包产物缺少运行期数据文件的问题**。`admin/data/upstream_error_messages.json` 未被打包进 EXE 与 APK，导致安装包启动时直接报错退出；现已随两个平台一并打包。
- **修复并发请求追踪 ID 重复**。独立请求的消息 ID 和无会话标识时的追踪 ID 改用随机生成，避免 Windows 系统时钟精度导致短时间内的多个请求被混淆；显式会话的轮次关联保持稳定。
- **完善运行隔离与异常脱敏**。本地客户端继续使用独立配置与数据库；余额刷新时的本地异常详情会隐藏令牌等敏感信息。保留后台守护启动与日志输出行为。

## 下载与升级

| 平台 | 安装包 |
| --- | --- |
| Windows x64 | `***-1.10.0-windows-x64.exe` |
| Android ARM64（Android 7.0 及以上） | `***-1.10.0-android-arm64.apk` |

Windows 使用新版 EXE 覆盖安装；安卓使用同签名 APK 覆盖安装，可保留账号与配置。两个安装包均提供对应的 `.sha256` 校验文件。

## 使用说明

- 「请求动态」的实时推送依赖普通 HTTP 长连接，若所处网络或反向代理不支持流式响应，界面会自动切换为低频刷新并在标题栏提示。
- 积分数据仍由定时任务刷新（默认每 2 小时），打开面板不会实时访问上游。
